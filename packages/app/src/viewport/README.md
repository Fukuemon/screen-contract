# live viewport の use case

Web UI から見た「対象アプリを開き、操作し、記録する」の実体。**合成ルートには
置かない** ([adr/0023](../../../../adr/0023-composition-root.md))。

| ファイル           | 責務                                                          |
| ------------------ | ------------------------------------------------------------- |
| `control.ts`       | Web UI からの操作の窓口。列挙外の origin を弾く (ADR-0017)    |
| `run-session.ts`   | run の保持と構成番号。**番号は画面状態ごとに持つ** (ADR-0005) |
| `session.ts`       | ブラウザセッションの寿命と配信の購読 (ADR-0008)               |
| `origins.ts`       | 実行してよい origin の列挙。追加は設定へ書き戻す (ADR-0017)   |
| `auth-profiles.ts` | 認証プロファイルの保管 Port。世代を持つ (ADR-0022)            |
| `run-state.ts`     | モードと、Stream Proxy が中継条件に使う状態 (ADR-0008)        |
| `state-key.ts`     | 画面状態の鍵。query と fragment を落とす                      |

## 外へ出す形

`ViewportSnapshot` が **HTTP の応答そのもの**である。`packages/api` はこの型を
そのまま返し、`apps/web` は api 経由で同じ型を読む。

interface 層がそれぞれ手で写す形にすると、ずれても型検査が鳴らない。実際に、
項目が 1 つ欠けただけで画面が落ちた。

型を共有してもなお `apps/web` 側の実行時検証は要る。**古い server プロセスが
動いたまま新しい画面を読む**ことがあり、そのときの応答は現在の型と一致しない。

## 触るときの注意

- **`paused` の枠を広げない。** 操作モードと記録は `paused` の run の中でしか
  使えない (ADR-0002 / ADR-0008 / ADR-0026)。枠を広げると、実行中の run へ
  人の入力が混ざる
- **終端から戻る経路を残す。** run を走らせきると `paused` を離れる。戻る経路が
  無いと、そこで操作モードへ二度と入れなくなる
- **列挙を迂回させない。** UI から任意の URL を開けるようにしても、追加は明示的な
  操作として設定へ書き戻す (ADR-0017)
