# ADR-0002: 一時停止をステップ境界とし、pause 中の実ページ操作を許可して再開時に再検証する

## Status

承認

## Context

再生の制御（一時停止、再開、再実行）は MVP の中心の体験である。  
core/execution を設計する前に、一時停止中の画面の操作をどう扱うかを決める必要がある。

- 要素の選択そのものは、viewport の上の座標を Element Inspector に問い合わせる読み取りの操作で実現でき、実ページへの操作の転送を必要としない。
- 一方で、ドロップダウンを開いた状態の要素を採番したいときのように、編集中の探索として実ページの操作が要る場面がある。

## Decision

- 一時停止は、ステップの境界でだけ止める。
  - pause の要求は、実行中のステップが完了した後に停止する予約として扱う。
- 一時停止中の実ページの操作を許可する。
  - 要素を選ぶための座標の問い合わせは操作に含めず、常に行える。
- 再開するときは、通過したステップの期待状態を評価し直す。
  - 満たさなくなった最初のステップへ巻き戻して再実行する。
  - 冪等スキップにより、変化のない区間は速く通過する。

状態遷移の図と再開時の規則は、[冪等実行と再生制御の Design Doc](../packages/core-execution/DesignDoc.md#実行状態と再生制御) にある。

## Considered Options

| 選択肢                                                                                         | 強み                                                                                             | 弱み                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **採用:** ステップの境界で止め、一時停止中の実ページの操作を許可し、再開時に再検証して巻き戻す | 探索を妨げない。再開時の状態の保証に既存の冪等の仕組みを使え、専用の状態の復元の仕組みが要らない | 破壊的な探索の操作は、巻き戻しでも復元できない場合がある。長いワークフローでは巻き戻しの再実行に時間がかかる                                          |
| 閲覧だけにする（操作を転送しない）                                                             | 再開が最も単純で、再現性も高い                                                                   | 探索的な操作を禁じると、止めて編集する体験が痩せる。ドロップダウンなどの状態は、すべて DSL の到達手順として先に書く必要があり、編集のループが長くなる |
| 設定で 2 つのモードを切り替える                                                                | —                                                                                                | 実装の量と検証のパスが倍になる。再検証と巻き戻しがあれば、操作を許可するモードだけで安全性を保てる                                                    |
| 命令の単位で即時に停止する                                                                     | 応答性が高い                                                                                     | ステップの中の中途半端な状態からの再開と再検証が複雑になる                                                                                            |

命令の単位の停止を採らないのは、再開の位置が常にステップの境界にそろう単純さを優先するためである。

## Consequences

### Positive

- 「draft は自由、確定は承認」の考え方とそろい、エージェントと利用者の探索を妨げない。
- 再開時の状態の保証が、期待状態の再評価という既存の冪等の仕組みの再利用で済み、専用の状態の復元の仕組みが要らない。

### Negative

- 破壊的な探索の操作（フォームの送信など）を行うと、巻き戻しでも復元できない場合がある。
  - 復元は、DSL の到達手順の再実行に頼る。
  - 外部の副作用の完全な冪等性は、[PRD の Non-Goals](../PRD.md#non-goals) に当たる。
- 長いワークフローでは、巻き戻しの再実行に時間がかかる。
  - 冪等スキップで緩和する。
