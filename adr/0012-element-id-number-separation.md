# ADR-0012: 永続要素 ID と表示用の構成番号を分ける

## Status

承認

## Context

画面の要素の同一性を、何で表すかを決める必要がある。

画面仕様書では、要素を構成番号（1..N）で参照する慣習がある。  
構成番号は、要素の追加、削除、読み順の変更のたびに振り直される。

構成番号を要素の識別子に使うと、振り直すたびに Locator、Expectation、差分の追跡のすべての参照が無効になる。  
同じ要素へ別々の番号や名称が割り当てられる問題も、検知できない。  
出典: [PRD の Background](../PRD.md#background)

## Decision

- 要素の同一性は永続要素 ID（画面の中で一意の slug、変更しない）で表し、構成番号は表示だけに使う。
- DSL の中の参照（`ref`。Locator の対象、Expectation、操作の対象、badges）は、すべて要素 ID で行い、構成番号を識別子に使わない。
- 構成番号は、状態ごとの `badges` の順序のリストの位置として表し、要素定義そのものは番号を持たない。
  - ADR-0005: [構成番号は状態単位で採番し、badges リストを基準に読み順の再採番で管理する](0005-renumbering.md)

## Considered Options

| 選択肢                                                         | 強み                                                                               | 弱み                                                                                         |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **採用:** 永続要素 ID で同一性を表し、構成番号は表示だけに使う | 再採番と読み順の変更が参照を壊さない。版の間と状態の間の要素の追跡が ID で安定する | 利用者は、仕様書に現れない内部の ID を、DSL を編集するときに扱う必要がある                   |
| 構成番号を識別子に使う                                         | —                                                                                  | 再採番ですべての参照が無効になり、版の間と状態の間の要素の追跡（差分の検知の前提）ができない |
| 要素の名称を識別子に使う                                       | —                                                                                  | 名称は仕様の改善で変わる。同じ名前のボタンが複数ある画面のように、名称の重複も許したい       |

## Consequences

### Positive

- 再採番と読み順の変更が、参照を壊さない安全な操作になる。
  - 番号の対応表（旧から新）を、要素 ID を基準に機械的に作れる。
- 版の間と状態の間の要素の追跡が ID で安定し、要素の差分（Role の変更、文言の変更など）を分類できる。

### Negative

- 利用者は、仕様書に現れない内部の ID を、DSL を編集するときに扱う必要がある。
  - Web UI の要素の選択と候補の提示で、この負担を軽くする。
