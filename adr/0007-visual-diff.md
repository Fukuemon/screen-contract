# ADR-0007: 画像差分は生スクリーンショットを対象に、Pixel Diff → 知覚差分の 2 段階で判定する

## Status

承認

## Context

core/diff を設計する前に、画像差分の実装の方式と、既定の閾値を決める必要がある。

- 比べる対象は、viewport を固定し、fixture で決定的に再現した画面どうしであり、レンダリングの環境の揺れは小さい前提がある。
- 一方で、日時の表示のように、fixture でも固定しきれない動的な領域が実画面にある。
- 注釈済みの画像（バッジを描き込んだ後）を比べると、番号の変更と画面の実際の変化が同じ差分に入り、分類できない。

## Decision

- 画像差分の対象は、生のスクリーンショット（バッジの合成の前で、`clip` を適用した後）にする。
  - 注釈済みの画像は、差分の検知の対象にしない。
  - 構造の変化は要素差分（Snapshot に基づく）が受け持ち、画像差分と分ける。
- 判定は 2 段階にする。
  1. Pixel Diff（アンチエイリアスを許すピクセルの比較）で差分のピクセルの比率を計算し、閾値以下なら「画像の変更なし」にする。
  2. 閾値を超えたときだけ、知覚差分（構造の類似度）を計算し、「画像の変更（意味のある変化）」と「軽微な揺れ（要確認）」に分ける。両方の指標をレポートに並べて書く。
- 閾値は、差分のピクセルの比率の既定値をシステムの設定に持ち、状態の単位で上書きできる。
- 動的な領域は、DSL の state に `mask`（除外する領域のセレクタの列）を宣言して除く。
  - mask は、撮影時に解決した bounding box の矩形として適用する。
  - 適用した領域をレポートに明示し、何も知らせずに無視しない。

判定の流れと分類は、[変更差分の検知の Design Doc](../packages/core-diff/DesignDoc.md#画像差分の-2-段階判定) にある。

## Considered Options

| 選択肢                                                                                                 | 強み                                                                                                                                         | 弱み                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **採用:** 生のスクリーンショットを、Pixel Diff と知覚差分の 2 段階で判定し、動的な領域は `mask` で除く | 番号を変えただけで画像差分が出ない。確認が要る差分の数が実際の変化に絞られる。知覚差分の計算は閾値を超えたときだけで、コストの増加は限られる | 知覚差分の類似の閾値というチューニングの項目が増える。mask の領域の中の本当の変化は検知できない                                        |
| Pixel Diff だけ                                                                                        | 最も単純                                                                                                                                     | 閾値をわずかに超えるレンダリングの揺れ（フォントのヒンティングなど）が、すべて「画像の変更」として出され、確認のコストが利用者にかかる |
| 知覚差分だけ                                                                                           | 人間の見え方に近い                                                                                                                           | 小さくても意味のある変化（アイコンの 1px の欠けなど）を「類似」と判定しうる                                                            |
| 注釈済みの画像を比べる                                                                                 | 生成物どうしの比較で、実装が楽                                                                                                               | 番号の変更とバッジの移動が画像差分に入り、差分を分類できるという、このプロダクトの中心の価値を壊す                                     |
| mask なし（fixture ですべて固定する）                                                                  | 理想                                                                                                                                         | 対象のアプリの協力の度合いに依存する                                                                                                   |

検知の一次の判定は、機械的な Pixel Diff に置く。  
fixture の整備を推奨しつつ、mask を明示的な逃げ道として残す。

## Consequences

### Positive

- 番号を変えただけで画像差分が出ることがなくなり、差分のレポートが画面の実際の変化だけを指す。
- 2 段階の判定により、確認が要る差分の数が実際の変化に絞られる。
- mask を適用した領域がレポートに残るため、除外しすぎて見逃すおそれを見える形にできる。

### Negative

- 知覚差分の類似の閾値という、チューニングの項目が増える。
  - 既定値をシステムの設定に持ち、まず既定値のまま運用する。
- mask は除外である以上、領域の中の本当の変化は検知できない。
  - 乱用を防ぐため、適用した領域の明示を必須にする。
