# 記録 UI の手動確認手順

**E2E では検証できない。** E2E は Browser Port を fake へ置き換える設計 (入れ子
ブラウザを避けるため) であり、記録の実挙動が通らない ([context/testing.md](../../context/testing.md))。
記録の UI 操作は手動で確かめ、結果をここと PR の description に残す。

## 前提

```sh
pnpm browser:install   # ブラウザ本体 (未取得のとき)
pnpm build
```

## 手順

| #   | 操作                                                      | 期待する結果                                              |
| --- | --------------------------------------------------------- | --------------------------------------------------------- |
| 1   | `pnpm --filter @screen-contract/web dev` で Web UI を開く | エディタ画面が出る。viewport は「接続していません」       |
| 2   | 「操作モード」を押す                                      | 押せない (再生中は入力を受け付けないため無効)             |
| 3   | run を一時停止させる                                      | 「操作モード」が押せるようになる                          |
| 4   | 「操作モード」を押す                                      | 操作モードへ切り替わる。記録の表示は「記録していません」  |
| 5   | 「記録を開始」を押す                                      | 表示が「記録中」へ変わる                                  |
| 6   | viewport 上のボタンをクリックする                         | 対象アプリのモーダルが開く。step が `ref` で記録される    |
| 7   | 「選択モード」へ戻す                                      | 記録が止まり、表示が「記録していません」へ戻る            |
| 8   | 承認画面を開く                                            | 「承認」が押せない (差分を表示していないため)             |
| 9   | 「差分を表示」を押す                                      | 差分が出て、「承認」が押せるようになる                    |
| 10  | Expectation を選ばずに承認しようとする                    | 「期待状態を持ちません」の警告が出る (承認自体は妨げない) |
