## 作業ステップ (この順序で実行する)

### ステップ 0: ブランチ準備と着手記録

ブランチ命名と base branch は `context/project.yml` の `naming.branch` および `workflow-git` に従う。

1. 対象 issue の `status:*` が `status:implementing` でなければ付け替え、状態遷移コメントを残す (`workflow-git` の `references/issue-status.md`。既に implementing なら何もしない)
2. 最新の base branch を取得する
3. 作業ブランチ `feature/4` を作成する (既にある場合は最新へ追従させる)
4. PR テンプレートを確認し、完了条件を description に転記する
5. Draft PR を作成して push する

### ステップ 1: バッジ配置の計算

1. テストを先に書く (端・重なり・ずらしの境界ケース)
2. `packages/core-artifact` にバッジ配置の純粋計算を実装する
3. バッジは bounding box の**左上角の外側**に固定オフセットで置く。画像の端にかかる場合は box の内側へ倒す
4. バッジ同士が重なる場合は読み順で後の要素を右へずらす。決定的に解決できない重なりは生成警告として報告する
5. 検証コマンドを実行する
6. diff レビューを回し、指摘を対応する

### ステップ 2: 注釈画像 (SVG) の生成

1. テストを先に書く (同じ入力から同じ SVG テキストが出ること)
2. **SVG のテキストを生成する純粋計算**として実装する。画像合成ライブラリを core へ入れない
3. 生スクリーンショットを `<image>` で**相対参照**する
4. 検証コマンドを実行する
5. diff レビューを回し、指摘を対応する

### ステップ 3: 構成要素テーブルと書き換え抑止

1. テストを先に書く (mtime が変わらないこと)
2. 状態ごとの Markdown テーブルを構成番号順に生成する
3. **書き換え抑止をテキスト比較 (完全一致) に統一**する。生スクリーンショットのみハッシュ比較とする
4. 出力先がプロジェクトルート配下に収まることを 2 段 (文字列検査 + 解決後の格納範囲検査) で検証する
5. 検証コマンドを実行する
6. diff レビューを回し、指摘を対応する

### ステップ最終: 最終確認

1. 全テスト / lint / typecheck がパスすることを確認する
2. spec の `## 上位資料からの変更点` に必要な追記がないかを確認する (durable な変更が出た場合のみ)
3. PR を Ready に変更しレビュアーを指名する

## 設計仕様

- **撮影と注釈は 2 段に分離する。** 撮影は adapter/browser、注釈 (バッジ配置の計算と SVG の組み立て) は core/artifact の純粋計算である。生スクリーンショットと bounding box は保存し、バッジは何度でも再合成できる。
- **注釈画像は SVG。** 生スクリーンショットを別ファイルとして保存し、SVG から相対参照する。既定は `<state-id>.svg` と `<state-id>.raw.png` で、同じディレクトリに置く。
- **書き換え抑止はテキスト比較 (完全一致) に統一する。** 以前は注釈画像だけが「生成入力の比較」という別規則を要していた。SVG はテキストなので Markdown / POM と同じ規則で判定できる。
- **差分検知の対象は生スクリーンショットであり、注釈画像は対象にしない。** 番号の変更が画面の実変化と混ざるためである。
- **再採番では生スクリーンショットを触らない。** `badges` の並べ替えで変わるのは SVG のテキスト数行だけである。
- **出力先はプロジェクトルート配下に限る。** 絶対パス・`..`・`~` 始まり・解決後にルート外を指すシンボリックリンクを拒否する。文字列検査だけではシンボリックリンクを通してしまうため 2 段で検査する。

## テスト観点

- 決定性: 同じ DSL + 同じ撮影結果から、バッジ配置・テーブル内容・SVG テキストが常に同一であること
- バッジ配置: 端・重なり・ずらしの境界ケース。解決不能な重なりの警告
- テーブル: 番号順、状態ごとの独立性
- 書き換え抑止: 入力同一で書き換えないこと (**mtime も変わらないこと**)。1 箇所の変更で該当成果物だけが更新候補になること。**再採番で生スクリーンショットが書き換わらないこと**
- 出力先: 絶対パス・`..`・`~` 始まり・解決後にルート外を指すシンボリックリンクが拒否されること
